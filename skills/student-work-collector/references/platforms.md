# 플랫폼별 수집 요령

필요한 플랫폼 부분만 읽는다. 사이트 화면은 자주 바뀌므로, 아래와 다르면 지금 보이는 화면을 기준으로 판단한다.

## 목차
- 캔바 (Canva)
- 패들렛 (Padlet)
- 클래스팅AI (Classting)
- 하이클래스 (Hiclass)
- 그 밖의 사이트
- 화면 캡처로 받는 경우

---

## 캔바 (Canva)

### Canva 커넥터가 있을 때 (`mcp__Canva__*`)
도구가 지연 로딩되어 있으면 ToolSearch로 필요한 것만 불러온다.
1. 학생 결과물 위치 찾기
   - 캔바 교육용 "과제/수업"으로 받은 경우, 학생 제출물이 선생님 계정의 폴더나 공유 디자인으로 들어온다. `search-folders`로 과제 이름 폴더를 찾고 `list-folder-items`로 디자인 목록을 얻는다.
   - 폴더가 없으면 `search-designs`로 과제 이름(예: "독서포스터")을 검색한다.
   - 선생님이 디자인 링크 목록을 줬으면 `resolve-shortlink`(짧은 링크)로 디자인 ID를 얻는다.
2. 학생 확인: 디자인 제목, 소유자/작성자 이름을 author로 쓴다.
3. 내보내기: `export-design`을 PNG 형식으로 호출한다(필요하면 `get-export-formats`로 확인). 여러 쪽 디자인은 쪽마다 PNG가 나오므로 같은 학생의 항목 여러 개로 적는다(스크립트가 `_2`, `_3`을 붙인다). 내보내기 결과의 다운로드 URL을 받아 작업 폴더에 저장한다.
4. 글 위주 디자인(글쓰기 활동지 등)이라도 요청이 "이미지로"면 PNG만. 선생님이 글도 원하면 `read-design`으로 글을 읽어 text 항목을 따로 만든다.

### 커넥터가 없을 때
- 공유 링크(보기 권한)는 브라우저로 열어 각 쪽을 화면 캡처하거나, 다운로드 메뉴가 보이면 PNG로 받는다.
- 가장 간단한 길: 선생님이 캔바에서 디자인을 PNG로 내려받아(여러 개면 zip) 올려 주는 것.

## 패들렛 (Padlet)

### 1순위: `scripts/padlet_to_manifest.js`
SKILL.md의 안내대로 실행한다. 게시물 데이터(`/api/10/wishes`), 작성자(`/contributors`), 댓글(`/comments`)을 받아 manifest를 만든다. 결과가 0개면 아래 브라우저 방법으로 읽는다.

### 브라우저로 읽기
1. 보드 주소(padlet.com/…)를 연다. 비공개 보드는 선생님이 로그인된 브라우저여야 한다.
2. 게시물(post)마다 작성자 이름, 제목, 본문, 첨부(이미지/파일/링크)를 읽는다.
   - 화면이 길면 스크롤하며 모두 읽었는지 게시물 수를 확인한다. 섹션(열)이 있는 보드는 섹션별로 확인한다.
   - 익명 게시는 작성자가 "익명"으로 나온다 → 제목이나 본문 첫 줄에 이름을 쓰는 경우가 많으니 거기서 찾는다.
   - 댓글은 기본적으로 모으지 않는다(선생님이 원하면 같은 학생 text 항목에 덧붙인다).
3. 이미지 첨부는 이미지 원본 주소를 받아 저장한다. 원본을 받을 수 없으면 게시물 화면을 캡처한다.
4. 선생님이 올린 안내 게시물, 보드 제목은 뺀다.

### 내보내기 파일
패들렛 보드 메뉴의 "공유/내보내기"에서 CSV·엑셀(글), 이미지·PDF(보드 전체) 내보내기가 된다. 선생님이 CSV/엑셀을 주면 열(작성자, 제목, 본문, 첨부 URL)을 읽어 manifest를 만든다. 첨부 URL이 있으면 내려받는다.

## 클래스팅AI (Classting)

- 로그인이 필요하다. 브라우저 도구가 선생님 컴퓨터의 로그인된 브라우저에 연결될 때만 직접 수집할 수 있다.
- 클래스 → 과제(또는 게시판/알림장 댓글)에서 학생 제출물을 연다. 학생 이름 옆에 제출 글, 첨부 이미지가 있다.
- 클래스팅은 학생 이름이 명렬표 기준으로 표시되는 경우가 많아 번호가 함께 보일 수 있다 → author에 보이는 그대로 적는다.
- 직접 열 수 없으면 선생님께: "클래스팅 과제 화면에서 학생 제출물을 내려받거나 캡처해 올려 주세요."

## 하이클래스 (Hiclass)

- 로그인이 필요하다. 클래스팅과 같은 방식으로 로그인된 브라우저를 쓴다.
- 과제 상세 화면에 학생별 제출 내용이 있고, 첨부 파일 "전체 다운로드"(zip)를 제공하는 경우가 있다. zip은 파일 이름에 학생 이름이 들어 있는 경우가 많으니 파일 이름을 author로 쓴다.
- 글 제출은 화면에서 본문을 읽어 text 항목으로 만든다.

---

## 그 밖의 사이트
구글 클래스룸(제출물 폴더가 구글 드라이브에 생김 → 드라이브 커넥터나 드라이브에서 내려받은 zip), 띵커벨, 미리캔버스, 북크리에이터 등도 같은 원리다: 작성자 + 글 본문 또는 이미지 파일을 모아 manifest에 적는다.

---

## 화면 캡처로 받는 경우
- 선생님이 게시판 전체 캡처를 주면, 캡처를 보고 학생별 글을 옮겨 적어 text 항목으로 만든다. 글자가 흐려 읽기 어려운 부분은 짐작하지 말고 `[판독 어려움]`으로 표시하고 선생님께 알린다.
- 학생 그림이 캡처 속에 여러 개 있으면 Pillow로 학생별 영역을 잘라 PNG로 저장해도 된다. 경계가 불분명하면 캡처 그대로 하나의 항목으로 둔다.
